## 4. 為什麼這個項目值得展示

### 4.1 一句定位

`NeuroFocus` 是一個把腦電波 / 專注代理輸入、3D 遊戲回饋、呼吸干預與結果量化結合的專注訓練互動平台。

### 4.2 核心賣點

- 不是單純答題遊戲，而是 `專注輸入 -> 即時回饋 -> 呼吸介入 -> 結果量化` 的完整閉環
- 同時結合 `EEG 硬體`、`Three.js 3D 視覺化`、`AI 題目 / 本地 fallback`
- 有 `真實 EEG` 也有 `Simulation Mode`，展示穩定性高
- 有訓練概念，不只是顯示數值

### 4.3 你們要一直強調的重點

- 本作品的重點不是「讀到腦波」本身，而是如何把專注狀態轉化成互動式訓練體驗
- 我們不是把數據丟在畫面上，而是讓數據改變船速、流程、介入與結果
- 即使真實 EEG 現場不穩，系統概念與訓練設計仍然完整成立

## 5. 目前遊戲運行邏輯

### 5.1 基本流程

1. 使用者輸入名稱
2. 進入 Setup
3. 選擇輸入模式
   - `EEG`
   - `Simulation`
4. 選擇難度
   - `Easy`
   - `Medium`
   - `Hard`
5. 進入遊戲
6. 一邊答題，一邊根據專注狀態推進船速
7. 低專注時觸發呼吸干預
8. 完局後進入結果頁

### 5.2 專注度驅動機制

- `focusLevel` 是核心輸入
- 專注度越高，船速越快
- 專注度越低，船速越慢
- 呼吸干預期間，遊戲暫停，避免玩家只是「硬撐」
- 回復後會給短暫 boost，讓玩家感受到介入效果

### 5.3 題目系統

- 優先使用 AI 題目生成
- 若 AI 過慢、失敗或回應無效，立即轉本地 fallback 題庫
- 題目主題已調整為較生活化、較適合展示
- 題目面板已可完整顯示題目與選項，不易截斷

### 5.4 呼吸干預機制

當 `focusLevel <= 45%` 並持續一段時間時：

- 先顯示低專注提示
- 若低專注持續超過 `5 秒`
- 進入呼吸干預 UI

呼吸干預期間：

- 遊戲暫停
- 計時停止
- 專注度與速度顯示歸零
- 玩家跟隨兩輪節奏呼吸
  - 吸氣 4 秒
  - 屏息 4 秒
  - 呼氣 4 秒

結束後：

- 短暫給予 `100% focus boost`
- 讓玩家感受到「調整狀態後可恢復表現」

### 5.5 結果頁量化

目前結果頁可展示：

- Distance
- Accuracy
- Total Time
- Focus Rate
- Recovery Time
- Breathing Count

這令項目由「顯示即時專注度」升級為「有介入、有回饋、有結果量化」。

## 7. 評審講解重點

### 7.1 開場 30 秒版本

「我們做的是一個專注訓練互動平台。使用者的專注狀態會即時影響 3D 船速，若專注下降太久，系統會觸發呼吸干預，最後再用結果頁量化整體表現。真實模式可接 EEG，展示模式則可用 Simulation，確保系統在會展現場仍然穩定。」

### 7.2 1 分鐘版本

「NeuroFocus 的設計目標是把抽象的專注訓練，變成可視化、可互動、可量化的體驗。系統有兩條輸入路線，一條是真實 EEG，另一條是穩定的 Simulation Mode。遊戲內不只是答題，還會根據專注狀態改變船速；當專注長時間下降時，我們加入呼吸干預，讓作品由監測升級為訓練。最後結果頁會顯示專注率、恢復時間與呼吸次數，讓使用者不只看到分數，也看到自己的狀態調節表現。」

### 7.3 3 分鐘版本講解結構

1. 問題背景：學生專注力不足，傳統訓練方式較抽象、較難持續
2. 解決方案：把專注輸入轉成即時 3D 遊戲回饋
3. 系統架構：
   - 網頁前端 SPA
   - Three.js 3D 遊戲
   - EEG Python Bridge
   - AI 題目 + Fallback 題庫
4. 訓練設計：
   - 專注驅動船速
   - 呼吸干預
   - 結果量化
5. 展示策略：
   - 真實 EEG 作高亮功能
   - Simulation 作穩定主線
6. 未來方向：
   - Camera 專注代理
   - Dashboard / 長期追蹤
   - 更完整前後測研究設計

## 8. 評審可能會問的問題與建議回答

### Q1：你們的作品和普通教育遊戲有什麼不同？

建議答法：

- 我們不只是答題，而是把專注狀態直接連接到遊戲速度與結果
- 作品包含輸入、回饋、介入、量化四個層次
- 這使它更接近「互動式專注訓練平台」而不是單純小遊戲

### Q2：為什麼要用 EEG？如果 EEG 不穩定怎麼辦？

建議答法：

- EEG 可以提供真實的即時專注輸入，是我們技術亮點之一
- 但現場展示需要穩定，所以我們設計了 Simulation Mode 作備援
- 這不是取代 EEG，而是讓系統在不同環境都能完整示範核心邏輯

### Q3：Simulation 是否只是假的展示？

建議答法：

- Simulation 是為了確保會展、教學、公開體驗時不受硬件限制
- 它的目的是穩定展示同一套訓練邏輯，而不是偽裝成真實 EEG
- 我們會清楚標示模式來源，確保誠實展示

### Q4：呼吸干預為什麼有意義？

建議答法：

- 如果系統只顯示你分心，那只是監測
- 我們希望在低專注時給使用者一個簡單、立即可操作的調節方法
- 呼吸介入把作品由「看到狀態」提升為「嘗試恢復狀態」

### Q5：你們如何證明真的有助改善專注？

建議答法：

- 現階段我們把作品定位為訓練概念原型
- 現在已能量化專注率、恢復時間、呼吸次數等指標
- 下一步是設計更完整的前測 / 後測與長期追蹤

### Q6：如果網絡很差，AI 題目會不會卡住？

建議答法：

- 我們已加入 timeout + fallback 題庫機制
- 即使 AI 過慢或失敗，也不會阻止遊戲開始
- 這是為了確保現場展示穩定

### Q7：為什麼不用手機鏡頭直接做專注偵測？

建議答法：

- 我們已規劃 Camera 專注代理作下一階段方案
- 但為了隱私與精準度，目前展示主線仍以 EEG / Simulation 為主
- 未來可用 Camera 作更低門檻的輸入模式

### Q8：你們的技術深度在哪裡？

建議答法：

- SPA 架構、Three.js 遊戲渲染、Python Bridge、AI 題目生成、Fallback 題庫、呼吸干預與結果量化都由我們整合
- 作品不是單一技術，而是跨硬件、前端互動、訓練設計與展示策略的整體系統

## 13. Pros 與 Cons

### Pros

- 主題清晰：專注訓練而非普通遊戲
- 展示感強：3D 航行 + 即時 HUD + 呼吸介面
- 可分層示範：一般觀眾玩 Simulation，評審看 EEG 架構
- 有介入設計：不只讀數，還會引導調節
- 有量化結果：可談未來研究與成效評估

### Cons

- EEG 實機穩定性仍不足
- 改善專注度的證據鏈仍偏弱
- Simulation 尚未等同 Camera 專注代理
- AI 題目仍受外部服務與網絡影響
