# NeuroFocus 會展展示執行簡報

日期：2026-06-24\
適用場景：香港會展現場展示、創科比賽攤位示範、校內外評審講解

## 1. 執行摘要

整體展示方案可行，而且建議採用雙軌制展示：

1. `Windows Laptop + 兩個 EEG 裝置` 作為真實 EEG 展示位
2. `個人 iPad + 參觀者自備手機` 作為公開網站與模擬模式展示位

此安排的最大優勢，是把高風險的硬件連線示範，與高穩定度的網頁互動示範拆開。Laptop 負責「完整功能」與技術深度，iPad 與手機負責「流暢體驗」與多人參與。這種前台用平板、後台用電腦的混合方式，本身亦符合展覽與會展常見的設備分工邏輯。

建議現場不要把全部成敗押注在 EEG 裝置即時取數上，而是以「網站可玩、模擬模式穩定、EEG 可作加分展示」作為主策略。由於目前 EEG bridge 仍受裝置權限、藍牙/serial、系統環境限制影響，因此明天的成功標準應調整為：

- 最低成功：參觀者可用 iPad / 手機進入網站並體驗模擬模式
- 標準成功：Laptop 可演示真實 EEG 流程或至少完整展示 EEG 連接介面
- 額外加分：至少一部 EEG 裝置可成功連線並展示專注度驅動船速

## 2. 展示架構與可行性判斷

### 2.1 建議展示架構

#### A. EEG 展示位

- 裝置：學校 Windows Laptop
- 功能：真實 EEG 模式、橋接程式、裝置連接示範
- 主要用途：
  - 給評審看「系統有真實腦波輸入設計」
  - 展示 EEG 模式的專注度驅動遊戲邏輯
  - 解釋本產品與一般單純網頁小遊戲的差異

#### B. 公開互動展示位

- 裝置：個人 iPad
- 功能：網站首頁、Setup、模擬模式、呼吸干預 UI、結果頁
- 主要用途：
  - 給一般參觀者快速體驗
  - 維持攤位穩定互動
  - 避免所有人都等待 EEG 裝置配戴與校正

#### C. 參觀者自帶手機入口

- 功能：掃 QR code 打開網站
- 主要用途：
  - 增加參與感
  - 擴大接觸面
  - 讓同組成員同時對多名參觀者講解

### 2.2 可行性判斷

整體是可行的，但要清楚區分以下三類風險：

#### 低風險

- 公開網站
- 模擬模式
- 題目互動
- 呼吸干預
- 結果頁展示

#### 中風險

- AI 題目生成速度
- 會展網絡不穩
- 平板/手機畫面兼容與效能波動

#### 高風險

- EEG 裝置當日藍牙/serial 連線
- Windows 權限與驅動問題
- Python bridge 無法即時收到穩定數據

### 2.3 建議現場策略

- 把 EEG 視為「高亮功能」而非唯一核心流程
- 把 iPad 模擬模式視為「保底體驗主線」
- 把手機掃碼體驗視為「人流互動入口」
- 若 EEG 失敗，仍可完整展示產品概念、遊戲流程、呼吸干預與結果量化

## 5. 目前遊戲運行邏輯

## 5.1 基本流程

目前網站流程為：

1. 使用者輸入名稱
2. 進入 Setup
3. 選擇輸入模式：
   - EEG
   - Simulation
4. 選擇難度：
   - Easy
   - Medium
   - Hard
5. 進入遊戲
6. 作答、航行、監測專注狀態
7. 完局後進入結果頁

### 5.2 遊戲核心邏輯

#### 專注度驅動船速

- `focusLevel` 為核心輸入
- 專注度越高，船速越快
- 專注度越低，船速越慢
- 暫停狀態下，專注度與速度顯示都會歸零

#### 題目系統

- 系統會先嘗試使用 AI 題目生成
- 若 AI 失敗、太慢或回應無效，會自動轉用本地 fallback 題庫
- 題目已改成較生活化、偏生物 / 化學 / 邏輯推理
- 題目面板現已可完整顯示題目與選項，不再截斷

#### 模式邏輯

- EEG 模式：
  - 嘗試透過 bridge 接收裝置專注數據
  - 若連接不成功，現場風險較高
- Simulation 模式：
  - 可穩定示範整體遊戲流程
  - 為明日公開體驗的主力展示模式

### 5.3 呼吸干預（P0）

呼吸干預現已完成第一版核心設計：

- 當 `focusLevel <= 45%`
- 先於畫面頂部出提示
- 若低專注持續超過 `5 秒`
- 便觸發呼吸干預 UI

呼吸干預期間：

- 遊戲暫停
- 計時停止
- 專注度顯示為 `0`
- 用戶跟隨兩輪節奏呼吸：
  - 吸氣 4 秒
  - 憋氣 4 秒
  - 呼氣 4 秒
  - 重複一次

呼吸引導結束後：

- 給予短暫 `100% focus boost`
- 讓玩家明顯感受到「成功回復專注」的正向反饋

### 5.4 結果頁量化

目前結果頁可展示：

- Distance
- Accuracy
- Total Time
- Focus Rate
- Recovery Time
- Breathing Count

這令項目由「只顯示即時專注度」提升到「有訓練介入與結果量化」。

## 7. 目前展示已有的 Pros 和 Cons

## 7.1 Pros

### 1. 主題清晰

- 產品不只是答題遊戲，而是「專注訓練 + 生理訊號 / 代理訊號 + 即時回饋」

### 2. 展示感強

- 3D 航行畫面、HUD、題目、呼吸介面都具有即時視覺回饋

### 3. 可分層示範

- 初階參觀者可玩模擬模式
- 評審可看 EEG / 設計原理 / 結果量化

### 4. 有訓練介入而非純監測

- 呼吸干預讓產品由「讀數」升級為「介入」

### 5. 有量化輸出

- 結果頁指標有利展示成效概念與未來研究方向

## 7.2 Cons

### 1. EEG 實機穩定性仍不足

- 現場可能無法穩定展示真實數據

### 2. 改善專注度的證據鏈仍偏弱

- 目前較接近「訓練概念原型」
- 尚未有嚴謹前後測設計

### 3. Simulation 模式目前仍未完全智能化

- P1 尚未完成前，仍然較像代理輸入而非真正視覺估算

### 4. AI 題目生成受外部服務影響

- 網絡、API、配額、延遲都可能影響示範

## 9. 明日現場建議展示流程

### 路線 A：一般參觀者 1 至 2 分鐘流程

1. 掃碼或用 iPad 打開網站
2. 輸入名字
3. 選擇 Simulation
4. 進入遊戲
5. 示範專注度與速度變化

### 路線 B：評審 3 至 5 分鐘流程

1. 介紹產品目標：幫助專注訓練
2. 說明輸入模式：
   - EEG
   - Simulation
   - 未來 P1 camera
3. 示範遊戲核心流程
4. 示範呼吸干預與結果頁
5. 若 EEG 成功，再示範真實裝置

### 路線 C：EEG 不成功時的備援流程

1. 先承認現場裝置連線受限
2. 說明系統已設計真實 EEG 模式與本機 bridge
3. 改以模擬模式示範完整閉環
4. 強調：
   - 真實輸入接口已存在
   - 現場示範主力改用穩定模式

## 12. 結論

以明天會展展示而言，現階段最合理的策略，不是追求所有功能完美上場，而是把「穩定可展示」與「高技術亮點」分開處理。Website、Simulation Mode、呼吸干預與結果頁，已足以構成一個完整、可互動、可解釋的展示主線；EEG 則作為增強說服力的進階示範。

只要團隊現場分工清晰，並準備好網絡、QR code、demo 截圖與 EEG 失敗備案，整體展示是可行的，而且有機會在評審面前呈現出「技術深度 + 體驗完成度 + 未來擴展性」三者兼備的印象。
